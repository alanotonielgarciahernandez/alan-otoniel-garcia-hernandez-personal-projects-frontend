# How to Contribute
Thank you very much for considering contributing to my projects. The following information are guidelines which helps us to communicate on an easy and understandable way to work on the best result.  
There are many ways to contribute, from reporting issues, features or improvements requests and writing code which can be incorporated into any of the projects.  
Support questions are not required to follow the guidelines.  
It is better to write your contributions being respectful, clear and without grammar errors.

## Report an issue
Bugs or security issues are handled through the same contact e-mail you can found at the end of the page. Ensure to answer the following questions first:

- Can I access something that's not mine, or something I shouldn't have access to?
- Can I disable something for other people?

In case both answers were "yes" you're probably handling a security issue, so add the syntax "[ Security Issue ]" to your e-mail subject and continue with the next steps, but, in case both answers were "no" and you are still unsure, add the same syntax and continue with the next steps.

### Make sure that is really an issue what you have found
Ask yourself why do you consider it an issue and how could that not be an issue, based on your answer decide if you should continue with the next steps.

### Try to replicate the issue
Make sure to remember the steps to replicate the issue and detail them on the report. This is a very important step that helps me to find the source of the issue.

### Detail the effects of the issue
List all the consequences caused by the issue. This will help to set the objective of the task.  

If you have more information or suggestions about the issue, you can add them at the end of your e-mail.

## Feature or improvement request
New ideas for any project are more than welcome, there might be no more reward than a mention, but your help is truly appreciated.

### Detail on a clear way your idea
Starting from the main function, tell me about the objective of the idea, why do you think it should be added and how you see the idea in the project.  
Also, since nothing is perfect, detail the aspects that your idea lacks and what disadvantages you think your idea could bring.

## About Spam
Sending a large number of e-mails in a short time, on the same subject, false reports, or meaningless messages will be considered as spam and the user will be blacklisted, and there is no way to undo that.
